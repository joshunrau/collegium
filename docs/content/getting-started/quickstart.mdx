---
title: Quickstart
description: 'From clone to a supervised first run: one agent, one task, one approval.'
---

In fifteen minutes, you'll run one agent, Clara, who researches on the live web and stops for approval before writing a file.

## Prerequisites

- Docker with Compose
- An API key for [OpenRouter](https://openrouter.ai/keys) or [DeepSeek](https://platform.deepseek.com/api_keys)

## 1. Clone and configure

```sh
git clone https://github.com/joshunrau/collegium.git
cd collegium
cp .env.template .env
```

Open `.env` and set `MATTERMOST_ADMIN_USERNAME` and `MATTERMOST_ADMIN_PASSWORD`. These become the Mattermost administrator credentials you log in with. Leave the remaining defaults.

## 2. Declare the agent

Create `config.json` at the repository root:

```json
{
  "$schema": "https://collegium.sh/api/config/schema.json",
  "agents": [
    {
      "username": "clara",
      "expertise": "research, summaries, and follow-through",
      "systemPrompt": "You are Clara, a careful researcher. Verify claims against sources before repeating them, and save your findings as files.",
      "model": { "provider": "openrouter", "name": "anthropic/claude-sonnet-5" },
      "tools": ["web", "workspace", "memory"]
    }
  ],
  "models": {
    "openrouter": { "apiKey": "sk-or-..." }
  }
}
```

`tools` lists everything Clara can do: browse the web, write files in her workspace, and keep memory.

## 3. Start it

```sh
docker compose up
```

The first start takes a few minutes. The stack is ready when the system bot posts its boot notice in the team's Town Square.

## 4. Log in and say hello

Open [http://localhost:8065](http://localhost:8065) and sign in with the admin credentials from `.env`. You land in the team's Town Square, and Clara is in the member list.

Clara answers only when mentioned. Give her a first task:

> @clara Find the three headline features of the latest Mattermost release and save a short summary to mattermost-notes.md

## 5. Watch the turn

Three things happen, in order.

**A status post.** Clara's status post appears and updates in place as she works. Each line names a tool call and what it does, including every page she visits.

**The approval prompt.** When Clara tries to write the file, the turn blocks. The prompt shows the exact path and the entire file body.

**The confirmation.** Click Approve. The tool runs, the file lands in Clara's workspace under `./state/workspaces/`, and Clara posts that she is done.

Run the task again and click **Deny with reason** instead. Clara receives your reason as the tool result and continues with it.

To see every tool call from a turn with its full arguments and results, run `/trace` in the channel.

## Shutting down

```sh
docker compose down
```

State persists under `./state`: the Mattermost data, the conversation store, and Clara's workspace. Starting again resumes the deployment.

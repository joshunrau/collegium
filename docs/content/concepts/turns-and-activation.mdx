## The Turn

The turn is the unit of execution: one activation of one agent in one channel. A turn assembles context, calls the model, executes tools, produces output, and terminates. Locking, budgeting, tracing, and failure handling all operate on turns.

Posting is the framework's job, not a tool the model calls. Text the model emits alongside a tool call becomes transient status. Text emitted with no tool call is the turn's final output, and posting it ends the turn.

## How a Turn Starts

Every activation is a Mattermost post. There are five kinds:

1. A human posts in a DM with the agent.
2. A human posts in a respond-to-all channel.
3. A human mentions the agent in a channel.
4. Another agent mentions the agent.
5. The system bot posts a trigger that mentions the agent.

There is no other path. No scheduler reaches an agent directly, no API wakes one, and an agent can't wake itself. If an agent is working, a post in the channel started it.

## Triggering Modes

You declare per channel how it treats human posts. The default is mention-required: the agent acts only when explicitly addressed. A channel can opt into respond-to-all, where every human post starts a turn. DMs behave that way inherently. A respond-to-all channel can hold at most one agent. Otherwise every human post would start a turn for each agent present, producing concurrent turns on the same task. The framework checks this at boot and on every membership change.

## Triggers

External events reach agents through triggers. Code such as a mailbox poll or a webhook endpoint records the event durably. The system bot then announces it in the target channel with a post that mentions the agent, starting an ordinary turn. The announcement carries the event's content in full, so the channel holds the record rather than a preview of it.

Announcements are idle-gated. A trigger posts only when its channel has no turn running, no approval pending, and nothing about to start. A busy channel holds the trigger until it next goes idle. The agent marks the trigger handled through a tool. Where the source owns part of that resolution, completion runs there first; mail, for example, marks the message read. Code decides when there is nothing to report. There is no path where an agent runs and stays silent.

## Fragment Folding

People type in fragments, seconds apart. A short window before each turn absorbs further messages from the same person. A mention followed by the actual request a beat later becomes one turn rather than a turn and a stranded message. A fragment arriving after the turn has started is absorbed too, while the turn is still on its first model call. The turn discards the completion that saw only half the request and re-reads the channel. Absorption ends at the first action. Only unaddressed posts are absorbed; a post that names the agent again is new work and queues as such.

## One Agent per Mention

A post mentioning two or more agents present in the channel starts no turn. The system bot answers with a correction to address one agent per message. Two agents given the same task would produce two turns and two competing approval prompts for overlapping actions.

The rule also pins delegation width at one. An agent's turn can hand work to at most one colleague, so a chain of handoffs stays a chain. Combined with the depth limit on agent-to-agent chains, that bounds the total work a single request can fan out into.

## The Context Window

Each turn assembles its context fresh: the agent's system prompt, its skill manifest, its memory descriptions, its peer roster, its tool definitions, and the channel window. The channel window is recent posts from the current channel, interleaved with the traces of this agent's own past turns there, walked backwards until a token budget runs out. An agent never sees a peer's trace. It reads colleagues through their posts alone.

Context is ordered by recency only. There is no threading, so no structural marker separates one piece of work from the next. Old work falls out of the window as the channel moves on. When you want a hard boundary, `/reset` marks an episode boundary that context never reaches past. Any human in the channel can use it.
